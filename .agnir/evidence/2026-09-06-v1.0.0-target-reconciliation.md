## Reconciliation rule

The accepted staging snapshot is used as product/package input, not as target continuity. The target candidate therefore:

- preserves Project identity exactly;
- preserves authoritative logical lineage identity exactly;
- binds that lineage to `refs/heads/main`;
- carries stable Core/profile/promotion contracts and version `1.0.0`;
- carries historical compatibility surfaces unchanged;
- carries accepted staging/RC evidence as receipts;
- rewrites State/Next Actions for target-specific release work;
- leaves stable publication `not-armed`.

No release-lineage selector or logical lineage identity is allowed to become authoritative through copying.

## Acceptance boundary

The candidate must first pass full CI on its validation ref. Immediately before main advancement, `main` must be re-read and still equal the captured target base. Only then may the candidate commit advance `main` coherently. The resulting exact main revision must receive its own successful CI before any publication-arm commit is created.
