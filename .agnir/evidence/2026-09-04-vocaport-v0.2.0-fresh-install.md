# VocaPort published Agnir v0.2.0 fresh-install evidence

Date: 2026-09-04

## Why this Project matters

`iorLab/VocaPort` is materially different from Svif and FishUp: it is a Rust-first offline-first application spanning Rust/WASM Web, Tauri/native Desktop, and Android, with independent bilingual Agent/README rules and no pre-existing Agnir binding at the captured source. It was selected to pressure non-destructive fresh installation rather than another migration path.

## Authorization and captured source

The Principal explicitly authorized a real Agnir `v0.2.0` fresh-install validation on VocaPort.

- captured authoritative main: `18a30d0dd745dadd128042d2439318b3f8c3e47c`;
- captured tree: `65894ef44dd93c23e74f5499a45cdde69ebb2e28`;
- no pre-existing `AGNIR.yaml`;
- target published Agnir: `v0.2.0` -> `fc84095ed5d500be9e1b43a4af0e93356571bbd4`.

## Non-destructive validation

The validation line used Project identity `urn:agnir:project:vocaport` and a validation-only logical lineage separately bound to its validation ref. Published Agnir reference implementations were used for AGENTS locator merge, activation, and `repository-filesystem/0.2` fresh discovery.

Repeated validation proved:

- existing `AGENTS.md` survives as an exact prefix with only the canonical Agnir locator appended;
- existing README survives as an exact prefix with only `## Agnir Project Instructions` appended;
- existing `AGENTS.zh.md`, `AGENTS.en.md`, `README.zh.md`, `README.en.md`, product source/config, package/lock/config files, and existing release workflows remain unchanged;
- official activation resolves the repository entry path;
- official Core/profile 0.2 discovery resolves Project identity, selected lineage, State, Next Actions, Decisions, and Evidence.

## Differential product baseline

Because VocaPort had no general pull-request CI and its clean Linux baseline required repository-specific WASM/Tauri prerequisites, the install was compared against an untouched branch derived from the captured main using the same runner/bootstrap.

Installed line:
- head `8db71e828e571e6f5f3c3a54fee8696ad3a39855`;
- run `33769051389`.

Untouched baseline:
- head `4004b57c68ad5bd2638526253446540eae64ef6e`;
- run `33769075075`;
- assertion confirmed the product tree differed from captured main only by the diagnostic workflow.

Both lines produced the same verification shape:

- WASM bootstrap: success;
- `pnpm typecheck`: success;
- Web build: success;
- downloads build: success;
- `pnpm test`: failure;
- `cargo check -p vocaport_native_shell`: failure.

Therefore the two failures reproduce without Agnir and are VocaPort baseline/environment limitations, not Agnir fresh-install regressions.

## v1 impact

This is the third materially different external real Project with direct published Core/profile 0.2 evidence, alongside Svif and FishUp. Under the current v1 minimum threshold, the **>=3 real Projects gate is satisfied**.

This does **not** close the separate execution-surface/adapter gate: VocaPort's Web/Desktop/Android product runtimes are application surfaces, not distinct Agnir execution surfaces. Agnir was still exercised through repository/filesystem semantics and GitHub Actions validation.

No Agnir Core/profile `0.2` semantic defect was exposed.
