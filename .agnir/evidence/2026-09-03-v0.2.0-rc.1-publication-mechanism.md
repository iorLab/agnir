# v0.2.0-rc.1 publication mechanism

Date: 2026-09-03

Direct tag/release creation is not exposed by the currently connected GitHub mutation surface. RC publication therefore uses a repository-owned GitHub Actions publication job rather than substituting a branch for a tag or weakening the release contract.

The job is part of `.github/workflows/conformance.yml` and depends on the ordinary `repository-filesystem` conformance job. It receives `contents:write` only when:

1. the event is a push;
2. the ref is exactly `refs/heads/release/v0.2.0-rc.1`;
3. the head commit message is exactly `rc: arm v0.2.0-rc.1 publication`;
4. the complete conformance job succeeds first.

Publication behavior is idempotent and fail-closed:

- if tag `v0.2.0-rc.1` is absent, create a lightweight tag ref directly at `GITHUB_SHA`;
- if the tag already exists, it must already point to `GITHUB_SHA`; otherwise fail and never move it;
- if the GitHub Release is absent, create it for that tag with `prerelease=true` and `draft=false`;
- if the Release already exists, reuse it only for the same tag;
- final verification requires tag SHA = `GITHUB_SHA`, `prerelease=true`, and `draft=false`.

Final pre-publication candidate `79f8eb071d0b29bc4505d3448550c55619bd7cc9` passed exact-head run `33675222129`. The publication-arming commit changes the workflow and durable continuity, so it must pass the complete conformance job again before its dependent publication job may create the tag/release.

This Evidence records mechanism and authorization, not publication success. Actual tag target, Release id, and workflow receipt must be captured after the publication job succeeds, without retagging.
