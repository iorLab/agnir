The branch was created from verified authoritative-main checkpoint `f0b2cbd5329adb6ac7309076d7ea09337bb057c5`, whose CI run `33653383024` passed all stable, Core `0.2`, migration, and full-suite gates.

## Preserved Project truth

Migration preserves:

- Project identity `urn:agnir:project:agnir-core`;
- durable memory locators `.agnir/state.md`, `.agnir/next-actions.md`, `.agnir/decisions.md`, `.agnir/evidence/`;

The compatibility-line change does not re-initialize the Project and does not relocate durable memory merely to introduce lineage semantics.

## New selected lineage and binding

The RC branch establishes:

- logical lineage: `urn:agnir:lineage:v0.2.0-rc.1`;
- VCS selector: `refs/heads/release/v0.2.0-rc.1`.

These values are intentionally different. The branch name/ref is a backend selector/binding; it is not logical lineage identity. A commit SHA remains a revision/checkpoint receipt rather than identity.

The migration publishes the Core/profile declaration, logical lineage, selector binding, Current State, Next Actions, RC version/release contract, and RC self-host CI route in one coherent branch revision so the branch does not expose a visible half-migrated self-host state.
