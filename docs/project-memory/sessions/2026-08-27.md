## Repository-backend CI/CD side-effect finding

- Tree Hole's CI runs on every push and its production deployment listens for successful `main` CI. Several memory-only migration commits therefore created redundant production Worker deployments even though executable source did not change.
- The final observed redundant deployment, Deploy Worker run `33049706193`, successfully deployed repository source commit `c07bd1bb4dd1a3e9e84c176378e174084f700c59`.
- Reconciled Tree Hole's durable state in one atomic Git checkpoint, commit `42ed6a14f05c6839ff70a1a995dff9d35f11ff8d`, using `[skip ci]`; GitHub reported zero workflow runs for that commit, validating the consuming repository's mitigation.
- Promoted the reusable lesson into `backends/REPOSITORY.md`: memory-only checkpoints should avoid unrelated production CI/CD when a supported mechanism and project policy allow it, should be coalesced when practical, and must not conflate persistence verification with application/release verification.
- This is backend operational behavior, not a PPMP Core semantic change. `spec/VERSIONING.md` permits backend evolution independently, so PPMP remains **v2.0.0**.
