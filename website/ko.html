사용법

네 단계면 충분합니다.

Agnir는 일상 작업에 부담을 더하지 않습니다. “” 의도를 표현하면 복구 가능한 Checkpoint를 남깁니다.

01

설치

위의 한 줄 설치 지시를 Agent에 전달합니다.

02

평소처럼 작업

개발, 디버깅, 리뷰, 커밋, 리팩터링을 지금처럼 계속하세요. Agnir는 개발 흐름을 대체하지 않습니다.

03

Checkpoint

의미 있는 구간에서 “” 의도를 전달하세요. Agnir가 현재 프로젝트 상태를 복구 가능한 형태로 남깁니다.

04

새 세션에서 계속

새 세션을 열고 “계속”이라고 말하세요. Agent가 프로젝트에서 Agnir를 다시 불러와 마지막 Checkpoint부터 작업을 이어갑니다.

걱정부터 없애기

기존 작업 방식을 바꿀 필요 없습니다.

특정 Agent에 묶이게 되나요?

아닙니다. Agnir의 연속성은 프로젝트에 속하며 특정 Agent, 모델, 채팅, 실행 환경에 속하지 않습니다.

모든 채팅 기록을 저장해야 하나요?

아닙니다. Agnir는 세션을 넘어 정말 남겨야 할 소량의 프로젝트 사실만 보존하며, 채팅 기록을 프로젝트의 진실로 취급하지 않습니다.

Git, IDE, 개발 흐름을 대신하나요?

아닙니다. 기존 도구는 그대로 사용하면 됩니다. Agnir는 지속 가능한 프로젝트 상태를 찾고, 불러오고, Checkpoint하는 역할만 합니다.

또 다른 불투명한 메모리 시스템인가요?

아닙니다. 다음 작업, 결정, 근거는 읽을 수 있는 Markdown 문서로 프로젝트 안에 남습니다.

마지막으로 개념

그래서 Agnir는 무엇인가요?

Agnir는 Project Continuity(프로젝트 연속성) 프로토콜입니다. 새 Agent가 안전하게 이어서 작업하는 데 필요한 소량의 지속 가능한 프로젝트 사실을 프로젝트 자체에 남기는 이식 가능한 규약입니다.

01

현재 상태

지금 확정되어 있는 것.

02

다음 작업

다음에 무엇을 어떤 순서로 할지.

03

결정

다음 Agent도 지켜야 할 제약과 선택.

04

근거

복구, 검토, 이전, 정렬을 검증할 수 있는 기록.

도구를 넘나들도록 설계

Agent를 바꿔도, 프로젝트는 그대로.

Agnir Core는 Git, GitHub, 파일 시스템, ChatGPT, 특정 Agent, Skill, 저장소 엔진에 종속되지 않습니다. 이들은 Project Continuity 계약을 둘러싼 도구일 뿐, 프로젝트를 특정 도구에 묶는 중심이 아닙니다.
